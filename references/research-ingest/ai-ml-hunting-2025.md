## CONCEPTS

### A. Model-format attack taxonomy

- **Two broad MFV categories — deserialization and backdoors.** Deserialization = payload injected during model loading via improperly handled serialized data; backdoors = hidden malicious functionality embedded in the model itself that alters inference under specific conditions. Both are in scope for huntr's model-format program; the categories are explicitly "not exhaustive" (S16). [methodology] `[superseded-risk]` — S16 describes the pre-2.0 program; the *taxonomy* itself is format-agnostic and survives, but verify current huntr challenge scope before relying on the program framing.
- **"Model files are archives in disguise."** `.nemo`, `.keras`, `.pth`, many `.onnx` bundles are zip/tar containers under a fancy extension; one-liner APIs like `model.from_pretrained()` hide the extraction step, so sloppy extraction slips in unnoticed (S7). Any loader that does a raw `extractall()`/`extract()` on attacker-influenced model files is a hunting target. [technique] — still valid 2026 technique class (format-level, not time-bound).
- **TarSlip/ZipSlip two primitives:** (1) path-traverse with `../` sequences or absolute paths; (2) symlink entries — an innocent-looking folder entry whose type/linkname points outside the sandbox; symlinks beat naive `../` filters (S7, S20). `tarfile` filter-parameter PoCs: rewrite `member.name` to `../../tmp/hacked`, or set `member.type=SYMTYPE, linkname=TARGET`. [technique]
- **Archive-slip alone is "basically dead" for bounties in 2025 (scanner catches `../../etc/passwd`), but it's the quickest write-anywhere primitive** — chain it into load-time code execution, model backdoors/output tampering, or scanner evasion, and it becomes high-value (S7). Pivot ladder: traversal → write-anywhere → config overwrite / second-stage planting / SSH key drop → RCE. [methodology]
- **Bounty value tiers (huntr MFV program, mid-2025):** high value = `.safetensors`, `.gguf`, `.keras`, `.joblib` + load-time ACE via header/metadata abuse + backdoors/output manipulation + scanner-evasion; medium-low = `.pkl` and fringe formats, plain Zip/TarSlip, bugs that fire only after extra imports, DoS via oversized tensors (S7, S16). Rewards: up to $4,000 per validated MFV; `.pkl` ≤ $750, other formats ≤ $1,500 (S16, S2). [methodology] `[superseded-risk]` — **pre-huntr-2.0 economics.** huntr announced the 2.0 challenge-based pivot 2026-06-08, stopped accepting OSS submissions 2026-06-30, and the MFV program page is "sunsetting soon" as of 2026-08-15. Do not quote these reward numbers as current.
- **Consumer-library attacks beat "safe" formats.** Unit 42 found RCE in three libraries (NVIDIA NeMo CVE-2025-23304, Salesforce uni2TS CVE-2026-22584, Apple/EPFL ml-flextok) where model *metadata* (YAML/JSON, even inside `.safetensors` `__metadata__`) is passed to `hydra.utils.instantiate()`, whose `_target_` accepts any callable — `builtins.exec` with a Python string achieves RCE at load time. ~50 of 100+ HuggingFace model-adjacent Python libraries use Hydra (S11). [technique] — RECENT (2026-01-13), current technique. NeMo CVE-2025-23304 and uni2TS CVE-2026-22584 are patched; the *pattern* is the current play.

### B. Load-time code-execution techniques

- **Pickle `__reduce__` RCE:** `torch.save()`/`torch.load()`, `pickle.load(s)`, and joblib/dill/cloudpickle all reconstruct objects by calling `__reduce__`; a malicious class whose `__reduce__` returns `(os.system, ("touch /tmp/poc",))` executes on load. Framework-agnostic core-Python bug; hunt any code path that loads `.pkl`/`.pt`/`.bin`/`.joblib` model files or tutorials that say "just load this .pkl" (S3, S5). [technique] — timeless class; the 2025-era framing "pays least" is economics, see `[superseded-risk]` above.
- **Keras Lambda layers:** serialized Python functions stored in the HDF5 (`.h5`) model file; executed at load/inference. PoC: `Lambda(lambda x: eval("__import__('os').system('touch /tmp/poc')" or x))`; malicious code bakes into the file at `model.save()`. Rule of thumb: "loading arbitrary Keras models = loading a script file" (S4, S1). [technique]
- **CVE-2025-1550 — config-as-executable-description:** the `.keras` file is a ZIP containing `config.json`; Keras `_retrieve_class_or_fn` used `importlib.import_module(module)` + `vars(mod).get(name)` on attacker-controlled `module`/`class_name`, then called it with attacker-controlled args — RCE even with `safe_mode=True`. Exploitable from `config.json` alone via `model_from_json` (no `.keras` file needed) (S6, S9, NVD). Fixed in Keras 3.9 via module allowlist (keras/keras_hub/keras_cv/keras_nlp) + safe_mode default + type checks (S9). [technique] — historical CVE (patched 2025); usable as a 1-day/sibling-hunt reference, not as a live target.
- **Post-fix gadget-function abuse (GHSA-c9rc-mg46-23w3):** safe_mode only blocks the `__lambda__` class name; reusing *approved-module* functions works — `keras.utils.get_file` with attacker-controlled `origin`/`cache_dir` downloads a remote file to any local path → arbitrary file overwrite → drop `~/.ssh/authorized_keys` → full SSH RCE. Because the payload contains no raw Python code, it sails past safe_mode and the import allowlist (S10). General pattern: after a deserialization fix, hunt "gadget functions" inside the newly allowed module set. [technique] — advisory (CVE-2025-8747) published 2025-08-12, updated 2026-05-29; the *pattern* is the live part, the specific Keras gadget is patched/version-dependent.
- **GGUF parsing bug classes (retr0reg, CVE-2024-25664…25668):** unchecked `n_kv` key-value count, unchecked string length (`0xffffffffffffffff` → allocation wraparound), unchecked tensor count — all produce heap overflows in `gguf_init_from_file()`/`gguf_fread_str()` style parsers. Pattern: `malloc(header.field * sizeof(T))` + `for (i < header.field)` where header values are attacker-controlled. Memory-corruption bugs in ML loaders "often occur where file parsing meets memory allocation" (S1, S2, S14). [technique]
- **`.llamafile` (APE) backdooring:** inject a payload into constant/static regions of the APE setup block that are identical across model versions; use substitution-based injection (`&&` command chaining) and keep payload size equal to the replaced content so ELF entry points/headers stay intact; executes at startup during the APE prep stage, bypassing integrity checks because it lives in a "trusted, unaltered" region. Mozilla deemed it not-a-vuln (design limitation), but the *technique* transfers to any self-executing model container (S15). [technique]
- **ONNX custom operators / control flow = native-code surface:** custom ops registered in native code (C++/CUDA) and If/Loop control-flow nodes execute during load; docs phrases like "full ONNX compatibility" or "custom operator support" are red flags if no sandboxing is mentioned (S1). [technique]
- **Safetensors is "safe" only as a format:** header is JSON metadata + raw tensor buffers, 100 MB header limit as DoS guard, no executable content — but consumer libraries execute the metadata (ml-flextok even uses `ast.literal_eval` on `__metadata__` strings then `instantiate()`; `literal_eval` is CE-only but enables memory/CPU-exhaustion, and the follow-on `instantiate()` gives full RCE) (S11, S18). [technique] — RECENT source (2026-01-13); current.

### C. Scanner-evasion tricks (hunter's toolkit; also the "what to test" list when verifying scanners)

- **ModelScan evasion taxonomy — 13 documented categories (issue #338, 2026):** (1) dangerous functions absent from the denylist; (2) *nested deserialization* — payload inside the argument of a deserialization call (`torch.storage._load_from_bytes` internally calls `torch.load(..., weights_only=False)`, scanner doesn't recurse); (3) *zipfile exception* — PyTorch's custom zip extractor vs stdlib `zipfile` mismatch crashes the scanner with `BadZipFile` while PyTorch loads fine; (4) *pickletools exception* — truncated opcode tail after the payload: `REDUCE` executes before the corrupted tail is reached, but `pickletools.genops` dies first; (5) *scanner-specific exceptions* — malformed operands after the payload (BINGET to unset memo key → KeyError, type-confused STACK_GLOBAL operands → TypeError, BYTEARRAY8 → unhashable); (6) *zlib-obfuscated payloads* — `zlib.decompress` itself isn't denylisted and the compressed blob hides `os.system` from pattern matching; (7) *Python-2 compat mapping* — `fix_imports=True` remaps `commands`→`subprocess` at runtime, `commands` isn't denylisted; (8) *CodeType/FunctionType construction* — raw bytecode via `marshal.loads` + runtime introspection, opaque to scanners; (9) *uncommon opcodes* — `copyreg.add_extension` + `EXT2`, or `INST` opcode with memo indirection; (10) *introspection chains* — `GLOBAL` opcodes reference only `builtins` (print → `object.__subclasses__()` → `eval` via `__init__.__builtins__`), beating allowlists; (11) *indirect model loading* — pickle that downloads another malicious model from the Hub during deserialization; (12) *extension/format mismatch* — raw pickle with a `.bin`/`.pt`/`.pth`/`.ckpt` extension gets routed to `PyTorchUnsafeOpScan`, which skips non-zip files without falling back to the plain pickle scanner (`torch.load()` accepts both); (13) *old TAR format* — pre-v1.6 PyTorch TAR archives load fine but the scanner's TAR path is unimplemented (S12). [technique] — RECENT (2026-03-23), current. Tested against ModelScan 0.8.8; issue still open as of 2026-06-25, so the gap set may have shifted — re-test against the latest release.
- **Denylist gaps → "0 issues" + full RCE:** ModelScan's pickle scanner is a blocklist over `pickletools.genops`-extracted globals; `importlib.import_module`, `operator.methodcaller`, `codecs.open`, `io.open`, `http.client` were missing → `importlib.import_module('os')` + `operator.methodcaller('system','id')` yields RCE with a clean scan (public PoC model `optimus-fulcria/modelscan-pickle-bypass-poc` on HF; ModelScan is used by HuggingFace as Protect AI Guardian) (S12 + linked PoC). [technique] — RECENT; same re-test caveat.
- **Two-repo cross-link bypass (zpbrent, HF):** craft an attack across two repos — one benign, one malicious — so `from_pretrained()` on the benign repo triggers code from the second, bypassing the Hub's pickle-import scan. Also: persistence pays — his initial report was rejected as "informative" and only became 2 CVEs after refining the PoC and re-demonstrating impact (S17). [technique] `[superseded-risk]` on the *specific* bypass mechanics (2024-era Hub scanning); the cross-repo linking *concept* and the persistence lesson remain valid — re-verify against current Hub scanner behavior.

### D. Tooling

- **ModelScan** (Protect AI, OSS): scans H5, Pickle-derived (incl. joblib/dill/cloudpickle), Keras v3, TF SavedModel, NumPy — reads bytes without loading, extracts `GLOBAL`/`STACK_GLOBAL`/`INST` imports via `pickletools.genops`, matches against the `unsafe_globals` severity blocklist; the lineage of PickleScan; also the engine behind Protect AI Guardian (used on HF Hub) (S18, S12). [tool] — still maintained; treat as *verification* tooling, not a pass/fail gate (see S12 evasion set).
- **HF Hub built-ins:** Hub runs ClamAV + pickle-import scans and displays imports per file; `pickletools.genops`-based, so it sees `GLOBAL` imports but not the evasion classes above; GPG-signed commits and `from_tf`/`from_flax` conversions are the recommended mitigations (S18, S17). [tool] — 2024-era description; Hub scanning specifics `[superseded-risk]`, re-verify current behavior.
- **Hunting stack (per the guides):** 010 Editor (hex), ASAN, GDB/LLDB, **AFL++ with structure-aware fuzzing** for parser bugs; `evilarc` for generating ZipSlip payloads; `objdump`/`readelf`/`elfedit` for PE/ELF/APE-style model containers; Fickling + PickleScan for static pickle analysis (S1, S2, S14, S20). [tool]
- **Protect AI Knowledge Base / Insights DB:** canonical PAIT detection IDs for model threats (e.g., PAIT-PKL-100/101, PAIT-KERAS-100/101, PAIT-ARV-100 archive-slip, PAIT-GGUF-101, PAIT-EXDIR-100 executable-config-targets) — a ready-made taxonomy to map findings to (S19). [tool] — KB page live and taxonomy content confirmed 2026-08-15; still the operative mapping taxonomy.

### E. Target-selection heuristics and hunting workflow

- **Pick targets where model-loading is a security boundary:** any tool whose docs say "we support loading arbitrary Keras models", "full ONNX compatibility", or that loads `.pkl`/`.h5`/`.safetensors`/`.gguf` from untrusted sources; DIY loaders in research repos are everywhere and use `extractall()` behind the scenes (S1, S7). [methodology]
- **Score surface by blast radius:** popular HF models with tens of millions of downloads; libraries with config-as-code patterns (Hydra usage is the tell: ~50 of 100+ model-adjacent libraries on HF); "modification of an existing popular model with a real or claimed benefit" is the attacker's (and hunter's) delivery vehicle (S11, S2). [methodology] — RECENT source; current.
- **Hunt files, not just APIs:** review model-loading entry points (`load_model`, `from_pretrained`, `restore_from`, `torch.load`, `load_weights`, `from_file`), then `hexdump` serialized files and mutate legitimate models — focus on header size fields, test extreme values (0, MAX_UINT64), feed malformed/truncated variants, check for integer overflow in `malloc(count * size)` and loops over file-read counters (S1, S2). [methodology]
- **Read documentation for flags:** keywords "arbitrary", "custom", "dynamic", "unsafe load options", "custom ops", "extensions", "callbacks" mark surfaces where format capabilities become code execution (S1). [methodology]
- **Escalate before you report:** taiphung217's method — study 1-day reports from top researchers (zpbrent, haxatron, kevin-mizu), find the sibling in the same codebase, then spend days chaining a minor primitive (arbitrary read) up to RCE/write before submitting; "aim for RCE-level impact when possible"; manual doc-reading for edge cases + Joern/AFL++ for automation (S8). [philosophy] — leaderboard framing is pre-2.0, the escalation discipline is not time-bound.
- **MFV report standard:** PoC model file hosted on a *public, gated* HF repo (Settings → Gated User Access → grant `protectai-bot` access), reproduction steps, explicit impact (ACE / silent output manipulation / scanner bypass); define the issue precisely, give reproducible evidence, analyze impact (S16, S15). [methodology] `[superseded-risk]` — submission channel described is the pre-2.0 huntr program; with the 2.0 challenge format (launch 2026-06-12) and the OSS program closed 2026-06-30, re-verify how MFV submissions are accepted today (the MFV form page says "sunsetting soon").
- **OWASP LLM Top 10 2025 as the mapping frame:** LLM03 Supply Chain, LLM04 Data and Model Poisoning (now covers malicious pickling + backdoors + "sleeper agent" triggers), LLM06 Excessive Agency, LLM10 Unbounded Consumption (widened from DoS to cost/model theft) — new-in-2025 entries LLM07 System Prompt Leakage and LLM08 Vector/Embedding Weaknesses reflect production RAG/agent reality (S13). [methodology] `[superseded-risk]` — **OWASP released the GenAI LLM Top 10 2026 edition (resource dated 2026-06-28); re-map findings to the 2026 codes and treat 2025 code mappings as legacy.**

### F. Defense patterns to know for verification work

- **Allowlist ≠ safe:** Hydra's new blocklist uses exact `_target_` matches and is trivially evaded via implicit imports (`enum.bltns.eval`, `nemo.core.classes.common.os.system`); NeMo's `safe_instantiate` is the stronger pattern — recursively walk all `_target_` values, actually *import* each one, then check it's a subclass of an expected class AND its resolved module is allowlisted (prefix matching alone is insufficient) (S11). [methodology] — RECENT (2026-01-13); current.
- **`safe_mode=True` is not a security boundary** in Keras — it's a UX flag (blocks `__lambda__` class_name only); verified twice: CVE-2025-1550 bypassed it via arbitrary module/function + args, GHSA-c9rc-mg46-23w3 bypassed it via gadget functions in approved modules (S6, S10). [methodology]
- **MLSecOps lifecycle control:** OpenSSF's 2025 MLSecOps whitepaper adapts SLSA/Sigstore/Scorecard to the ML pipeline and maps OWASP ML Top 10 threats per lifecycle stage — scan models before *and* after training, before deploy; checksums + cryptographic signatures for model integrity (S18, OpenSSF 2025-08-05). [methodology] — 2025 source; concept-level guidance remains valid, but re-check for a 2026 MLSecOps revision before citing.

## OUTDATED-OR-SUPERSEDED

Re-audited 2026-08-15: all of the following are `OUTDATED` (2025 or earlier) by the freshness rule and must not be treated as current technique. None are deleted — annotated instead. Where a concept is genuinely dead or overtaken, it says so; where only the specifics are stale but the class lives, that is flagged too.

- **"Pickle is the whole story" (2023-era lore) is dead.** 2025-2026 reality: the ecosystem moved to "safe" formats (safetensors, GGUF) and config-as-data, so the *consumer libraries* and *metadata* are now the attack surface — Hydra `_target_` chains, Keras `config.json` execution, scanner gaps in `.gguf`/`.keras`/`.joblib` paths. Pickle hunting still works but pays least (≤$750 vs ≤$1,500-$4,000) (S7, S11, S16). `[superseded-risk]` on the dollar figures — pre-huntr-2.0 economics; the direction (pickle pays least, consumer-library attacks pay most) is confirmed by the RECENT Unit 42 work (S11).
- **ZipSlip/TarSlip as a standalone finding is superseded** (scanners catch the trivial variants); it survives only as a write-anywhere pivot primitive (S7).
- **Keras `safe_mode` as a mitigation is superseded** — bypassed twice in 2025 (CVE-2025-1550, GHSA-c9rc-mg46-23w3 / CVE-2025-8747) (S6, S10). The gadget-function pattern it demonstrated remains the operative post-fix hunting technique.
